# 아이스브레이킹 웹앱 제작 지침

이 문서는 `icebreaking/` 아래의 새 게임을 만들거나 기존 게임의 핵심 진행, 효과음 또는 배경음악을 수정할 때 읽는다. 공통 구현 기준은 `webapp.md`, 카메라를 쓰는 활동은 `camera-webapp.md`, 완료 전 점검은 `verification.md`를 함께 따른다.

## 기본 방향

- 게임 이름만 보고 일반적인 미니게임을 만들지 않고, 실제 핵심 조작과 판정 흐름을 먼저 정한다.
- 처음 보는 학생도 짧은 설명 뒤 바로 참여할 수 있게 한다.
- 한 판의 목표, 남은 시간 또는 진행 상태와 성공·실패 결과가 한눈에 보여야 한다.
- 교실 활동이 멈추지 않도록 카메라·음성 인식이 실패해도 키보드, 터치 또는 교사 판정 같은 대체 경로를 제공한다.

## 소리 기본값

- 효과음과 배경음악은 기본적으로 켜진 상태로 시작한다.
- 첫 화면의 소리 버튼은 현재 상태를 정확히 반영해 기본 문구를 `소리 끄기`로 표시한다.
- 사용자가 언제든 효과음과 배경음악을 즉시 끄고 다시 켤 수 있는 명확한 버튼을 제공한다.
- 사용자가 소리를 껐다면 같은 실행 흐름 안에서 임의로 다시 켜지 않는다.
- 브라우저의 자동 재생 정책을 우회하지 않는다. 시작 버튼 등 사용자의 명시적인 동작에서 `AudioContext`를 생성하거나 재개하고, 그 전에는 실제 재생을 시작하지 않는다.
- 소리가 재생되지 않아도 게임을 시작하고 끝낼 수 있어야 한다.

## 배경음악 필수 제작

- 모든 아이스브레이킹 게임에는 게임의 분위기와 진행 속도에 맞는 배경음악을 제작한다.
- 배경음악은 외부 사이트에 핫링크하지 않는다. Web Audio로 직접 구성하거나 사용 권한이 명확한 최적화된 로컬 파일을 사용한다.
- 앱별 음원 파일은 해당 웹앱 폴더의 `audio/`에서 관리하고, 여러 앱이 실제로 함께 쓰는 음원만 `assets/audio/`에 둔다.
- 배경음악은 준비 카운트다운 또는 실제 플레이 중에만 재생하고, 일시정지·결과 화면·초기 화면·페이지 이탈 시 멈추거나 충분히 감쇠한다.
- 재시작이나 반복 플레이 때 음악 인스턴스, 타이머 또는 예약 음표가 중복되지 않게 한다.
- 게임 진행이 빨라지는 구조라면 템포나 리듬 밀도를 단계적으로 높일 수 있지만 갑작스러운 음량 상승은 피한다.
- 음성 명령이 핵심인 게임은 발화 중 음악을 낮추거나 단순한 리듬만 남겨 명령 전달을 방해하지 않게 한다.

## 효과음과 음량 균형

- 성공, 실패, 콤보, 시작과 종료처럼 즉시 알아야 하는 사건에는 서로 구분되는 짧은 효과음을 사용한다.
- 배경음악은 효과음과 음성 안내보다 작게 설정한다.
- 효과음을 너무 자주 겹치거나 날카로운 고음을 반복하지 않는다.
- 중요한 상태는 소리만으로 전달하지 않고 화면의 문구, 색, 모양 또는 움직임으로도 함께 보여준다.

## 온라인 기록판

여러 게임이 Firebase 프로젝트 `math-webapps-board` 하나를 함께 쓴다. 공용 모듈은 `assets/online-board.js`, 설정값은 `assets/firebase-config.js`, 보안 규칙·색인·시험은 `firebase/`에 있다. 슈퍼 세이브!(`keeper-reflex`)가 첫 적용 사례다.

- 개인정보를 받지 않는다. 저장하는 것은 별명, 게임 기록(레벨·점수·시간 등), 날짜, 익명 로그인 uid뿐이다. 실명·학번·카메라 영상은 받지 않는다.
- 시작 화면에 `🌐 온라인 기록판에 올리기` 체크 상자를 두고 기본은 켜 둔다. 끈 설정은 기기에 저장되어 모든 게임에 적용된다(`online-board-opt-v1`).
- 체크 상자 근처에 "별명·기록·날짜가 30일 동안 공개되며 실명·학번은 쓰지 말라"는 안내를 항상 보인다.
- 별명을 비우면 이 기기 기록판에만 남기고 온라인에는 올리지 않는다. 금칙어가 든 별명도 올리지 않는다.
- 결과 화면 기록판은 `🌐 오늘 / 🌐 30일 / 📱 이 기기` 탭으로 나눈다. 온라인 탭은 같은 난이도(board)끼리 비교한다.
- 올렸는지, 왜 못 올렸는지 한 줄로 알리고, `이 기기에서 올린 온라인 기록 지우기`를 제공한다.
- 인터넷이 없거나 Firebase가 막혀도 게임과 이 기기 기록판은 그대로 동작해야 한다. 모듈 함수는 예외를 던지지 않는다.
- 같은 기기는 10초에 한 번만 올릴 수 있다. 기록은 30일 뒤 만료되며, 무료 요금제라 TTL 대신 기록판을 본 기기가 지난 기록을 조금씩 지운다.
- 무료 읽기 한도(하루 5만 건)를 아낀다. 공개 기록판은 한 번에 15건만 읽고 같은 탭은 2분 동안 다시 읽지 않는다. 내 판이 목록 밖이면 정확한 순위 대신 개수만 세어 `오늘 올라온 128판 중 상위 12%`처럼 보인다.

### 그룹 (6자리 코드, 1시간)

- 상단의 `👥 그룹` 버튼(`assets/online-group.js`의 `mountGroup`)으로 누구나 그룹을 만들거나 코드로 들어간다. 교사 전용 화면은 두지 않는다.
- 그룹에 들어가 있으면 상단에 `👥 482 913 · 7명 · 52분`을 계속 보여, 만든 사람도 코드를 띄운 채 게임할 수 있다.
- 그룹 하나가 Firestore 문서 하나(`groups/{코드}`)라 순위를 볼 때 읽기 1번이다. 20초마다 읽되, 바뀐 게 없으면 40초·60초로 늦춘다. 게임 중과 화면이 가려졌을 때는 읽지 않는다.
- 한 판이 끝나면 그룹 칸과 공개 기록을 한 번의 트랜잭션으로 함께 저장하고, 그때 받은 그룹 상태로 화면을 바로 갱신한다(따로 읽지 않는다).
- 그룹 순위는 게임·난이도별로 위 5명만 이름을 보이고, 나는 `7명 중 4위`처럼 내 화면에만 정확히 보인다.
- 시작 화면은 그룹에 들어가 있으면 동작 소개 자리에 그룹 순위를, 결과 화면은 `👥 그룹` 탭을 먼저 보인다.
- 대화상자를 열 때 경기 중이면 일시정지한다. 1시간이 지나면 기기에서 그룹을 잊고 그룹 탭을 숨긴다. 나가면 그룹 문서의 내 칸도 지운다.
- 그룹은 60명까지이고, 같은 기기는 1분에 한 번만 그룹을 만들 수 있다. 끝난 그룹 문서는 누가 새 그룹을 만들 때 조금씩 지운다.

### 경기 화면 양옆 패널

- 카메라 영상(4:3) 밖 빈 공간에만 놓아 공·영상·터치 영역을 가리지 않는다. 양옆이 130px 이상이면 옆 패널(250px 이상이면 큰 글씨), 세로 화면처럼 위아래가 남으면 위아래 띠, 둘 다 좁으면 숨긴다.
- 왼쪽 기록판: 그룹 → 없으면 오늘 → 오늘 기록이 없으면 30일 → 인터넷이 안 되면 이 기기 기록. 내 줄은 한 줄이며, 이번 판이 내 최고 기록을 넘기 전까지는 `⭐ 나 · 최고 기록`을, 넘으면 `🔴 나 · 경신 중!`으로 지금 점수를 보인다(다시 시작해도 최고 기록이 순위에서 사라지지 않게). 누군가를 제치면 `⬆ n위!`가 2.5초 보인다. 공개 기록판 위 15건에 내 기록이 없으면 이 기기의 같은 별명·난이도 최고 기록을 쓴다. 옆 패널은 5줄, 세로 띠는 4칸이며 내가 그 밖이면 마지막 칸에 내 줄을 넣는다.
- 오른쪽 위 다음 목표: 먼저 내 최고 기록, 넘은 뒤에는 바로 위 사람(같은 레벨이면 남은 점수, 레벨이 높으면 그 레벨까지 남은 시간). 최고 기록을 넘고 1위면 경신 표시.
- 오른쪽 아래 반응 속도: 평균, 가장 빠름, 최근 10개 막대(평균보다 빠르면 초록, 평균은 점선). 막대 바닥은 0.3초 근처라 차이가 잘 보인다.
- 경기 중에는 시작 때 받아 둔 기록과 지금 점수로만 계산한다. 그룹만 `isPlaying`일 때 30초 이상 간격으로 다시 읽는다.

새 게임을 붙일 때:

1. `firebase/firestore.rules`의 `gameOk()`에 그 게임의 검사 함수를 추가한다. 칸 목록, board 값, 점수·시간 범위, `rank` 계산식을 정한다. 그룹에도 올리려면 `groupKeyOk()`에 `'게임~난이도'` 키를 추가한다.
2. `node firebase/test/rules-test.mjs`에 그 게임의 허용·거부 사례를 추가하고, 에뮬레이터에서 모두 통과시킨다.
3. `cd firebase && firebase deploy --only firestore`로 규칙을 배포한다. 운영 배포는 사용자 확인 뒤에 한다.
4. 게임에서 `submitScore(GAME_ID, { board, nick, rank, ...칸 })`와 `fetchBoard()`, `rankRange()`, `deleteMine()`을 부르고, 상단에 `mountGroup()`을 붙인다. 슈퍼 세이브!의 `startUpload()`·`renderBoard()`·`renderHeroGroup()`을 참고한다.
5. localhost에서 주소 끝에 `?emu=1`을 붙이면 에뮬레이터에 연결해 운영 데이터 없이 시험할 수 있다.

## 검증

- 첫 화면에서 소리 버튼이 `소리 끄기`로 표시되고 실제 초기 상태와 일치하는가?
- 시작 버튼을 누른 뒤 효과음과 배경음악이 재생되는가?
- 소리 버튼으로 즉시 끄고 다시 켤 수 있는가?
- 카운트다운, 플레이, 일시정지, 결과와 재시작 사이에서 음악이 겹치지 않는가?
- 탭을 가리거나 페이지를 벗어날 때 음악과 예약된 소리가 멈추는가?
- 배경음악이 효과음 또는 음성 명령을 가리지 않는가?
- 소리를 끈 상태에서도 모든 진행과 판정을 시각적으로 이해할 수 있는가?
- iPad A16 가로·세로 화면에서 소리 버튼이 잘리거나 다른 조작을 가리지 않는가?
