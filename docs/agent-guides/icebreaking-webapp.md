# 아이스브레이킹 웹앱 제작 지침

이 문서는 `icebreaking/` 아래의 새 게임을 만들거나 기존 게임의 핵심 진행, 효과음 또는 배경음악을 수정할 때 읽는다. 공통 구현 기준은 `webapp.md`, 카메라를 쓰는 활동은 `camera-webapp.md`, 완료 전 점검은 `verification.md`를 함께 따른다.

## 기본 방향

- 게임 이름만 보고 일반적인 미니게임을 만들지 않고, 실제 핵심 조작과 판정 흐름을 먼저 정한다.
- 처음 보는 학생도 짧은 설명 뒤 바로 참여할 수 있게 한다.
- 한 판의 목표, 남은 시간 또는 진행 상태와 성공·실패 결과가 한눈에 보여야 한다.
- 교실 활동이 멈추지 않도록 카메라·음성 인식이 실패해도 키보드, 터치 또는 교사 판정 같은 대체 경로를 제공한다.

## 소리 기본값

- 효과음과 배경음악은 기본적으로 켜진 상태로 시작한다.
- 첫 화면의 소리 버튼은 현재 상태를 정확히 반영해 기본 문구를 `소리 끄기`로 표시한다.
- 사용자가 언제든 효과음과 배경음악을 즉시 끄고 다시 켤 수 있는 명확한 버튼을 제공한다.
- 사용자가 소리를 껐다면 같은 실행 흐름 안에서 임의로 다시 켜지 않는다.
- 브라우저의 자동 재생 정책을 우회하지 않는다. 시작 버튼 등 사용자의 명시적인 동작에서 `AudioContext`를 생성하거나 재개하고, 그 전에는 실제 재생을 시작하지 않는다.
- 소리가 재생되지 않아도 게임을 시작하고 끝낼 수 있어야 한다.

## 배경음악 필수 제작

- 모든 아이스브레이킹 게임에는 게임의 분위기와 진행 속도에 맞는 배경음악을 제작한다.
- 배경음악은 외부 사이트에 핫링크하지 않는다. Web Audio로 직접 구성하거나 사용 권한이 명확한 최적화된 로컬 파일을 사용한다.
- 앱별 음원 파일은 해당 웹앱 폴더의 `audio/`에서 관리하고, 여러 앱이 실제로 함께 쓰는 음원만 `assets/audio/`에 둔다.
- 배경음악은 준비 카운트다운 또는 실제 플레이 중에만 재생하고, 일시정지·결과 화면·초기 화면·페이지 이탈 시 멈추거나 충분히 감쇠한다.
- 재시작이나 반복 플레이 때 음악 인스턴스, 타이머 또는 예약 음표가 중복되지 않게 한다.
- 게임 진행이 빨라지는 구조라면 템포나 리듬 밀도를 단계적으로 높일 수 있지만 갑작스러운 음량 상승은 피한다.
- 음성 명령이 핵심인 게임은 발화 중 음악을 낮추거나 단순한 리듬만 남겨 명령 전달을 방해하지 않게 한다.

## 효과음과 음량 균형

- 성공, 실패, 콤보, 시작과 종료처럼 즉시 알아야 하는 사건에는 서로 구분되는 짧은 효과음을 사용한다.
- 배경음악은 효과음과 음성 안내보다 작게 설정한다.
- 효과음을 너무 자주 겹치거나 날카로운 고음을 반복하지 않는다.
- 중요한 상태는 소리만으로 전달하지 않고 화면의 문구, 색, 모양 또는 움직임으로도 함께 보여준다.

## 검증

- 첫 화면에서 소리 버튼이 `소리 끄기`로 표시되고 실제 초기 상태와 일치하는가?
- 시작 버튼을 누른 뒤 효과음과 배경음악이 재생되는가?
- 소리 버튼으로 즉시 끄고 다시 켤 수 있는가?
- 카운트다운, 플레이, 일시정지, 결과와 재시작 사이에서 음악이 겹치지 않는가?
- 탭을 가리거나 페이지를 벗어날 때 음악과 예약된 소리가 멈추는가?
- 배경음악이 효과음 또는 음성 명령을 가리지 않는가?
- 소리를 끈 상태에서도 모든 진행과 판정을 시각적으로 이해할 수 있는가?
- iPad A16 가로·세로 화면에서 소리 버튼이 잘리거나 다른 조작을 가리지 않는가?
