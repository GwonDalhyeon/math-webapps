# 작업지시서 작성 지침

이 문서는 Codex, Claude Code 또는 다른 구현 도구가 읽을 작업지시서를 만들 때 읽는다.

## 위치

공개 가능한 교육용 기획서와 작업지시서는 `tasks/`에 둔다.

파일명은 다음 형식을 권장한다.

```text
YYYY-MM-DD-topic-name.md
```

예:

```text
2026-06-10-sample-proportion-event-readiness.md
```

비공개 임시 지시서, 개인 메모, 실험용 프롬프트는 `tasks/`에 두지 않는다.

## 작업지시서의 역할

작업지시서는 구현자가 다음을 혼동하지 않게 해야 한다.

- 만들 웹앱의 수학적 목표
- 왜 웹앱이어야 하는지
- 학생의 핵심 조작과 아하포인트
- 예상 오개념과 이를 줄이는 장치
- 기본값과 조작값
- 화면에 반드시 보여야 할 상태
- 수식 표현 방식과 교과서식 분수 렌더링 기준
- 프로젝터/전자칠판에서 조작과 결과가 함께 보이는 화면 배치 기준
- 어떤 파일을 만들고 수정해야 하는지
- 어떤 기술을 쓰면 안 되는지
- 완료와 검증 기준

## 작성 기준

- 구현자가 바로 작업할 수 있을 만큼 구체적으로 쓴다.
- 사전 학습가치 검토를 통과할 수 있도록 웹앱이 필요한 이유와 아하포인트를 분명히 쓴다.
- 기본값은 학습지 계산값과 맞춘다.
- `n`, `p`, 반복 횟수처럼 헷갈리기 쉬운 기호는 역할을 분명히 쓴다.
- 수학 모델은 고등학생 수준 설명과 구현 계산식을 함께 둔다.
- 분수, 제곱근, 확률식, 표준화 식처럼 구조가 중요한 수식은 교과서식으로 보이도록 LaTeX + MathJax 또는 MathML 사용 여부를 명시한다.
- 분수는 `1/2`, `(X-np)/σ`, `a/b`처럼 슬래시 텍스트로만 남기지 않도록 지시한다.
- 동적 수식이 있으면 조작 후 재렌더링 또는 DOM 갱신 기준을 적는다.
- 교사가 프로젝터나 전자칠판으로 보여줄 때 조작 영역과 핵심 결과 시각화가 한 화면 안에 함께 보이도록 화면 배치 기준을 적는다.
- 외부 라이브러리를 쓰지 않는 방향을 먼저 고려한다.
- CDN이 필요하면 이유와 오프라인 제약을 적는다.
- 실제 파일이 없는 링크를 만들지 말라고 명시한다.
- 웹앱에 맞는 학습지를 함께 만들 때는 Markdown/PDF를 웹앱 폴더에 두고, 웹앱 `index.html`의 제목/짧은 설명 아래에 다운로드 영역을 연결하라고 명시한다.

## 카메라 인식 조건 작성

카메라로 손, 몸, 얼굴 동작을 인식하는 웹앱의 작업지시서에는 `카메라 인식 조건` 항목을 두고 다음 세 가지를 반드시 지시한다. 세부 기준은 `camera-webapp.md`에 있다.

이 세 가지는 설계 단계에서 빠지면 나중에 고치기 어렵다. 구현자가 알아서 챙길 것으로 기대하지 말고 작업지시서에 문장으로 남긴다.

1. **무거운 모델의 지연 로딩과 vendoring**
   - 모델과 WASM을 `assets/vendor/` 아래에 두고 상대경로로 불러 오프라인에서도 동작하게 한다.
   - 처음에 모든 모델을 받지 말고 실제로 쓰는 화면에 들어갈 때 받는다.
   - 로딩 중 진행 표시를 보여준다.
   - GitHub Pages는 COOP/COEP 헤더를 설정할 수 없으므로 단일 스레드로 동작하게 한다.

2. **흔들림을 견디는 판정과 막혔을 때의 대체 경로**
   - 판정 방식을 활동에 맞게 지정한다. 자세를 맞히는 활동은 조건을 만족하는 상태가 0.3~0.5초 이어질 때 통과로 본다. 움직이는 대상을 맞히는 활동에는 유지 시간을 요구하지 말고, 판정 범위를 넉넉하게 잡고 이전 프레임과 현재 프레임을 이은 선분으로 접촉을 판정한다.
   - 화면에 표시하는 수치는 최근 몇 프레임의 평균으로 부드럽게 만들되, 빠른 동작 판정에는 원본 좌표를 쓴다.
   - 유지 시간, 판정 반경, 자동 통과 시간 같은 임계값은 코드 상단 상수로 모아 수업 중에도 조정할 수 있게 한다.
   - 계속 실패할 때 자동으로 넘어가거나 건너뛸 수 있게 한다.
   - 카메라가 없거나 권한이 거부된 학생도 활동을 이어갈 수 있게 한다.

3. **인식 상태를 항상 보여주기**
   - 인식된 랜드마크를 점과 선으로 겹쳐 그린다.
   - `손이 보이지 않습니다`처럼 지금 무엇이 필요한지 문구로 알린다. 색 변화만으로 구분하지 않는다.
   - 유지 시간이 필요한 판정에는 진행 표시를 보여준다.
   - 화면을 거울처럼 좌우 반전하고, 영상과 랜드마크 오버레이에 같은 반전을 적용한다. 좌우를 지시하는 활동이면 라이브러리의 왼손·오른손 구분이 촬영된 사람 기준이라는 점을 명시한다.

개인정보 조건도 함께 적는다. 카메라 영상을 띄우지 않고 랜드마크만 표시하는 것을 기본값으로 하고, 영상이 기기 밖으로 나가지 않는다는 문구를 화면에 표시하도록 지시한다.

구현 전에 로딩 시간과 단일 스레드 fps를 측정하도록 지시하고, 성능이 나오지 않으면 구현하지 말고 `재설계` 또는 `제작 보류`로 판정하도록 적는다.

좋은 예:

- 손 모델은 1단계 진입 시, 전신 모델은 3단계 진입 시 각각 받고, 받는 동안 진행 표시를 보여준다.
- 양손을 든 자세가 0.4초 이어지면 통과로 처리하고, 10초 동안 실패하면 건너뛰기 버튼을 보여준다.
- 파리 잡기는 유지 시간을 요구하지 않고, 손 위치의 이전 프레임과 현재 프레임을 이은 선분이 파리 반경 안에 들어오면 즉시 성공으로 처리한다.
- 인식된 손 랜드마크를 항상 겹쳐 그리고, 손이 화면에 없으면 `손을 카메라에 보여주세요`를 표시한다.
- 카메라 권한을 거부한 학생은 마우스로 파리를 클릭하는 방식으로 같은 단계를 진행할 수 있다.

피할 예:

- MediaPipe로 동작을 인식한다.
- 인식이 잘 되게 한다.
- 성능을 최적화한다.

## 학습가치 기준 작성

작업지시서에는 구현 전에 검토자가 판단할 수 있는 기준을 포함한다.

좋은 예:

- 학생이 슬라이더로 표본 크기를 바꾸면 표본비율의 흔들림이 작아지는 장면이 즉시 보여야 한다.
- 아하포인트는 "한 번의 결과는 흔들리지만 표본 크기가 커질수록 분포 전체가 좁아진다"이다.
- 판서만으로는 반복 표집과 분포 형성 과정을 동시에 보여주기 어렵기 때문에 웹앱이 필요하다.
- 오개념 방지를 위해 표본 크기와 반복 횟수를 서로 다른 조작으로 분리해 라벨링한다.

피할 예:

- 확률을 쉽게 이해하게 한다.
- 그래프를 예쁘게 보여준다.
- 학생이 재미있게 조작한다.

## 수식

작업지시서 자체의 수식은 구현자가 이해하기 쉬우면 텍스트 표기와 LaTeX를 함께 사용할 수 있다.

웹앱 화면에 표시되는 수식은 다음 기준을 지시한다.

- 구조가 중요한 수식은 LaTeX + MathJax 또는 MathML로 렌더링한다.
- 분수는 슬래시 텍스트가 아니라 `\frac{...}{...}` 또는 MathML `<mfrac>`처럼 교과서식 세로 분수로 표시한다.
- 화면에 원시 LaTeX가 그대로 보이지 않게 한다.
- 동적으로 값이 바뀌는 수식은 조작 후 다시 렌더링되게 한다.
- 수식은 그래프, 도식, 표, 현재 상태 문구와 같은 값을 가리키게 한다.

다만 학습지 Markdown을 생성하도록 지시할 때는 반드시 다음 규칙을 포함한다.

```text
학생용 학습지와 예시답안이 있는 교사용 학습지를 함께 제작한다.
학습지 Markdown의 모든 수식은 LaTeX 형식으로 작성한다.
인라인 수식은 $...$, 별도 줄 수식은 $$...$$ 형식을 사용한다.
웹앱 폴더에 Markdown/PDF를 함께 두고 웹앱에서 다운로드할 수 있게 연결한다.
```

## 완료 기준 작성

완료 기준은 기능 단위로 확인 가능해야 한다.

좋은 예:

- `1회 실행`, `10회 실행`, `100회 실행`, `자동 실행`, `일시정지`, `초기화`가 안정적으로 동작한다.
- 자동 실행 중 중복 타이머가 생기지 않는다.
- `n`, `p`, `r`을 바꾸면 준비 인원, 그래프, 해석 문구가 즉시 갱신된다.
- 브라우저 콘솔 오류가 없다.
- 분수와 구조가 중요한 수식이 교과서식으로 렌더링되고 원시 LaTeX가 보이지 않는다.
- 조작 후 동적 수식이 최신 값으로 갱신된다.
- iPad A16 가로 화면(`1180×820` CSS px)에서 핵심 조작과 결과 시각화가 첫 화면 또는 아주 짧은 스크롤 안에 함께 보인다.
- iPad A16 세로 화면(`820×1180` CSS px)에서 주요 버튼, 수식, 그래프, 결과 카드가 겹치거나 잘리지 않는다.
- 프로젝터/전자칠판 화면에서도 핵심 조작과 결과 시각화가 한 화면 안에 함께 보인다.
- 과목별 목록 페이지에 새 웹앱 링크가 추가되어 있다.
- 학습지 PDF/Markdown 다운로드 링크가 실제 파일을 가리킨다.

카메라를 쓰는 웹앱이면 다음을 추가한다.

- 처음 화면에서 필요하지 않은 모델까지 미리 받지 않는다.
- 자세 판정에 유지 시간이 적용되어 한 프레임으로 통과되지 않는다.
- 순간 접촉 판정에는 유지 시간을 요구하지 않고, 빠르게 지나가는 동작도 놓치지 않는다.
- 계속 실패할 때 건너뛰거나 자동으로 넘어갈 수 있다.
- 랜드마크 오버레이와 인식 상태 문구가 보이고, 화면이 거울처럼 좌우 반전되어 있다.
- 시작을 여러 번 눌러도 카메라 스트림과 추론 루프가 중복되지 않고, 정지 후 카메라 표시등이 꺼진다.

피할 예:

- 잘 만든다.
- 예쁘게 만든다.
- 오류가 없게 한다.

## 검증 방법 작성

검증 방법은 구현자가 따라 할 수 있는 순서형 체크리스트로 쓴다.

예:

```md
1. 웹앱을 브라우저에서 연다.
2. 기본값이 학습지와 일치하는지 확인한다.
3. `1회 실행`을 여러 번 눌러 결과가 달라지는지 확인한다.
4. 자동 실행을 켠 뒤 다시 눌러도 중복 실행되지 않는지 확인한다.
5. 분수와 구조가 중요한 수식이 교과서식으로 렌더링되는지 확인한다.
6. iPad A16 가로 viewport `1180×820`에서 조작 영역과 결과 시각화가 함께 보이는지 확인한다.
7. iPad A16 세로 viewport `820×1180`에서 주요 요소가 겹치거나 잘리지 않는지 확인한다.
8. 프로젝터/전자칠판 기준 화면에서 조작 영역과 결과 시각화가 함께 보이는지 확인한다.
9. 개발자 도구 콘솔에 오류가 없는지 확인한다.
```
