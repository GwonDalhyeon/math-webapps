# 카드 이미지 작업지시서 템플릿

이 문서는 특정 교과 또는 목록 페이지의 카드 이미지 작업지시서를 작성하거나 수정할 때 사용하는 공통 양식이다. 카드 이미지의 조사·스타일·승인·제작·적용 규칙은 `card-images.md`, 일반적인 작업지시서 작성과 공개 범위는 `task-spec.md`, 경로와 목록 페이지 구조는 `repo-structure.md`, 완료 전 검증은 `verification.md`를 따른다.

이 템플릿 자체를 `tasks/`에 복사해 빈 항목을 남겨 두지 않는다. 실제 웹앱을 조사한 뒤 해당 작업에 필요한 항목을 채운 문서만 저장한다.

## 사용 조건과 저장 위치

- 특정 교과 또는 목록 페이지의 카드 묶음을 기획할 때 사용한다.
- 공개 가능한 작업지시서는 `tasks/YYYY-MM-DD-<subject>-card-images.md`에 둔다.
- 비공개 임시 작업지시서는 `.work/claude-tasks/<subject>-card-images.md`에 둔다.
- 기존 작업지시서가 있으면 새 문서를 중복 생성하지 않고 원래 문서를 수정한다.
- 이번 단계가 작업지시서 작성 단계라면 실제 이미지 생성·수정·삭제, 이미지 파일 저장, HTML/CSS 적용, 커밋과 푸시를 하지 않는다.
- 사용자 승인 전에는 작업지시서에 작성한 이미지 생성 프롬프트를 실행하지 않는다.

## 작성 전 확인

다음 문서를 먼저 읽고 대상 목록 페이지의 각 카드가 가리키는 실제 `href`를 확인한다.

- `AGENTS.md`
- `CLAUDE.md`
- `docs/agent-guides/card-images.md`
- `docs/agent-guides/task-spec.md`
- `docs/agent-guides/repo-structure.md`
- `docs/agent-guides/verification.md`

카드 제목이나 소개 문구만으로 내용을 추측하지 않는다. 실제 대상 HTML과 연결된 JavaScript, CSS, Canvas, SVG, 3D 장면과 정적 리소스를 확인하고, 로컬 브라우저에서 주요 조작과 대표 상태를 관찰한다. 실행하거나 이해할 수 없는 앱은 추측해서 채우지 않고 확인하지 못한 내용과 원인을 기록한다.

## 제작 단계 승인 조건

- [ ] 모든 대상 카드의 실제 `href`를 확인했다.
- [ ] 모든 대상 웹앱의 주요 파일과 실제 동작을 확인했다.
- [ ] 초기 상태, 변화 과정과 대표 결과 상태를 관찰했다.
- [ ] 카드별 핵심 조작과 즉시 변하는 요소를 정리했다.
- [ ] 카드별 대표 장면과 스타일 참조 이미지를 선정했다.
- [ ] 카드끼리 구도와 변화 표현이 지나치게 반복되지 않는지 확인했다.
- [ ] 수학적으로 오해를 부르는 표현이 없는지 검토했다.
- [ ] 사용자가 카드별 시안을 명시적으로 승인했다.

마지막 항목까지 충족하기 전에는 실제 이미지를 생성하지 않는다.

## 작업지시서 단계 완료 기준

- [ ] 모든 대상 앱의 실제 동작을 조사했다.
- [ ] 카드별 시각화 근거와 피해야 할 오해가 기록되어 있다.
- [ ] 카드별 시안과 실행 가능한 개별 프롬프트가 준비되어 있다.
- [ ] 스타일 참조 이미지와 예상 파일 경로가 지정되어 있다.
- [ ] 실제 이미지 생성과 코드 수정은 수행하지 않았다.
- [ ] 사용자가 검토할 수 있는 압축 시안 요약을 제공했다.
