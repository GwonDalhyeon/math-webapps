# 고3 2학기 수업 안 듣는 이유 월드컵 작업지시서

웹앱 이름: 고3 2학기 수업 안 듣는 이유 월드컵
위치: `icebreaking/grade12-second-semester-excuse-worldcup/`
대상 학생: 고등학교 3학년, 특히 2학기 첫 수업 또는 PPT 도입 장면
수업 상황: 교사가 전자칠판으로 진행하는 2~5분짜리 참여형 아이스브레이킹
함께 만들 학습지: 만들지 않음

## 제작 상태 (전체 52장)

- 활성 카드: 52장. 카드별 3D 전시 이미지와 웹용 대사를 함께 제공한다.
- 현재 웹앱은 무작위 빠른 16강 또는 본선 32강으로 진행한다.
- 빠른 16강은 52장 중 16장을, 본선 32강은 52장 중 32장을 각각 중복 없이 추첨한다.
- 아직 이미지가 없는 사유는 링크·선택지·빈 카드로 노출하지 않는다.

## 1. 목적과 사용 원칙

### 목표

- 고3 2학기 특유의 교실 공기를 짧고 빠르게 공유한다.
- 학생이 두 문장 중 더 "고3 2학기답다"고 느끼는 문장을 선택하며 수업 첫 장면의 어색함을 푼다.

### 이 앱이 아닌 것

- 학습 성찰, 진로 상담, 출결 지도, 실제 학생의 상황 판정 도구가 아니다.
- 우승 문장 뒤에 훈계·교훈·반성 질문을 붙이지 않는다.
- 투표 결과나 학생 이름을 저장·전송하지 않는다.

### 웃음의 대상과 안전선

- 실제 학생의 외모, 성적, 가정환경, 진학 결과, 진로를 놀리지 않는다.
- 웃음의 대상은 "한 문장이 점점 더 대담한 다음 핑계로 진화하는 말의 구조"와 이를 물리적으로 과장한 장면이다.
- 이미지의 학생은 특정 학생과 닮지 않는 반복 등장용 가상 피규어다. 로고, 학교 마크, 실제 교복 식별 요소, 실사 인물을 쓰지 않는다.
- 수시 합격·면접·실기·취업처럼 실제로 성립할 수 있는 사유는 거짓말 또는 실패로 묘사하지 않는다. 과한 은퇴식, 기자회견, 연구소 장비 같은 **상황의 과장**으로 웃음을 만든다.

### 웹앱이 필요한 이유

PPT 한 장의 문장 나열보다, 두 카드의 이미지와 문장을 즉시 비교하고 대진표가 쌓이는 과정이 교실 전체의 반응을 빠르게 끌어낸다. 매번 다른 16개 또는 32개를 뽑을 수 있어 반복 사용에도 결과가 달라진다.

### 핵심 조작과 아하포인트

- 핵심 조작: 두 카드 가운데 더 "고3 2학기다운 대사"를 탭·클릭·키보드로 선택한다.
- 즉시 변화: 선택한 카드가 다음 라운드로 이동하고, 현재 대진·진행률·작은 대진표가 갱신된다.
- 아하포인트: 설명이 아니라, 각기 다른 이유가 같은 "고3 2학기 대표 대사" 자리를 두고 경쟁하는 과장된 게임 형식 자체다.

## 2. 게임 규칙과 진행 흐름

### 첫 화면

```text
고3 2학기 수업 안 듣는 이유 월드컵
둘 중 더 "고3 2학기답다" 싶은 대사를 고르세요.

[빠른 16강] [본선 32강] [소리 끄기]
```

- 기본 진입은 `빠른 16강`으로 한다. 15번 선택으로 끝나므로 PPT 도입에 적합하다.
- `본선 32강`은 교사가 시간을 넉넉히 쓸 때 선택한다. 31번 선택으로 끝난다.
- 시작할 때 전체 52개 중 해당 인원만 무작위로 추첨한다. 같은 판에서 문장은 중복되지 않는다.
- 교사가 원하는 구성을 즉시 만들 수 있도록 `고정 시드/재대진`은 구현 후 선택 사항으로 둔다. 초기 버전에는 무작위 대진과 `다시 뽑기`만 필수다.

### 한 대결 화면

- 제목: `16강 · 3 / 8`처럼 현재 라운드와 대결 순서를 표시한다.
- 왼쪽·오른쪽에 4:5 세로 이미지 카드와 정확한 핑계 문장을 함께 표시한다.
- 중앙 질문은 항상 `둘 중 더 고3 2학기다운 대사는?`으로 고정한다.
- 카드 전체를 클릭·탭할 수 있어야 하며, 키보드 `←` / `→` 또는 `A` / `D`도 같은 선택을 수행한다.
- 선택 뒤 250~400ms 동안 선택 카드의 테두리·트로피 표시·짧은 효과음을 보여 준 뒤 다음 대결로 넘어간다. 긴 애니메이션은 금지한다.
- 화면 상단 또는 하단에는 현재 라운드의 작은 대진표를 두되, 두 카드보다 눈에 띄지 않게 한다.

### 마지막 결과

1. 마지막 선택 뒤 0.8초 이내에 결과 화면으로 전환한다.
2. 우승 카드의 세로 이미지를 크게 보여 주고, 웹 글자로만 `🏆 고3 2학기 대표 대사`와 우승 문장을 표시한다.
3. 우승 문장이 이긴 경로(첫 대결 → 16강/8강 → 4강 → 결승)를 작은 카드 5장 이내로 보여 준다.
4. 우승 카드의 이미지와 대진 경로를 Canvas로 합성한 `결과 포스터 저장`을 제공한다. 이미지 안의 한글은 AI가 만들지 않고 브라우저 Canvas 텍스트로 얹는다.
5. `다시 뽑기`와 `처음으로`만 제공한다. 결론, 성찰, 훈계, 학습목표 문구는 결과에 넣지 않는다.

### 소리

- 아이스브레이킹 지침에 따라 배경음과 선택 효과음을 포함한다.
- 시작 버튼을 누른 뒤에만 Web Audio로 가벼운 게임쇼 리듬을 재생한다. 초기 화면에서는 자동 재생하지 않는다.
- 배경음은 낮고 짧은 리듬으로만 구성하고, 선택 효과음과 겹치지 않게 한다.
- `소리 끄기` 버튼은 첫 화면부터 보이며, 켜진 기본 상태와 문구가 일치해야 한다.
- 재대진·초기화·탭 숨김·페이지 이탈 시 루프와 예약 음표를 정리해 중복 재생을 막는다.

## 3. 이미지 시스템

### 공통 아트 디렉션

- 형식: 세로 4:5, 최종 배포용 `768×960 WebP`(원본 PNG 보관 가능), 카드당 목표 250KB 이하.
- 분위기: "고3 2학기 사유연구소"가 진지하게 전시한 **고급 3D 피규어·박물관 표본 사진**.
- 색: 옅은 회색 연구소, 코발트블루 주색, 필요한 곳에 경고등 오렌지. 카드들은 같은 색 역할과 조명 밀도를 공유한다.
- 인물: 같은 계열의 익명·초라한 가상 고등학생 피규어. 헝클어진 머리, 풀어진 넥타이, 구겨진 옷, 어색하고 눈치 보는 자세는 허용하되, 잔인함·신체 비하·공포 표현은 금지한다.
- 카드마다 한 가지 물리적 시각 농담만 중심에 둔다. 예: "오늘만"은 하루짜리 휴식권이 무한 출력되는 장면.
- 위쪽 18%, 아래쪽 15%는 카드 제목과 보조 태그가 올라갈 수 있도록 단순한 여백을 남긴다.
- 이미지 안에는 한글·영문·숫자·말풍선·로고·학교 마크·워터마크를 넣지 않는다. 정확한 문구는 HTML/Canvas에서 렌더링한다.

### 자산 파일 규칙

- 개별 카드: `icebreaking/grade12-second-semester-excuse-worldcup/assets/reasons/g3-01-math-not-needed.webp`처럼 번호와 영문 슬러그를 사용한다.

## 5. 화면, 데이터, 구현 구조

### 화면 구성

```text
시작 화면
  → 모드 선택(빠른 16강 / 본선 32강)
  → 대결 화면(좌·우 이미지 카드, 진행률, 축소 대진표, 음소거)
  → 라운드 전환
  → 결과 화면(우승 카드, 우승 경로, 결과 포스터 저장, 다시 뽑기)
```

### 배경과 시각적 위계

- 앱 전체 배경은 이미지 카드의 옅은 회색 연구소와 대비되는 **짙은 남청색 연구소 전시실**로 한다. 검은색·네온 사이버펑크가 아니라, 무광 남청 그라데이션 위에 아주 옅은 격자와 코발트 조명을 두는 방식이다.
- 배경 격자는 정보가 아니라 분위기 요소이므로 낮은 대비로 처리하고, 첫 화면의 카드 문장보다 눈에 띄지 않아야 한다.
- 카드 내부는 생성 이미지의 옅은 회색 연구소 공간을 그대로 살린다. 따라서 어두운 앱 배경 위에서 카드 이미지·한글 대사·선택 테두리가 명확히 분리된다.
- 강조색은 선택 전 코발트블루, 선택 순간과 우승은 제한된 오렌지/금빛으로만 쓴다. 색만으로 승패를 표시하지 않고 `선택됨`, 트로피 아이콘, 이동 애니메이션도 함께 쓴다.

### 대결 화면 레이아웃

- 상단 한 줄: 왼쪽에 게임명과 `16강 · 3 / 8`, 오른쪽에 `소리 끄기` 버튼을 둔다.
- 그 아래: 중앙 질문 `둘 중 더 “고3 2학기답다” 싶은 대사는?`와 얇은 진행 막대를 둔다.
- 핵심 영역: iPad 가로 화면에서 4:5 후보 카드 두 장을 좌우 동등 폭으로 배치하고, 가운데에는 작은 `VS`만 둔다. 카드 안에는 위쪽 이미지, 아래쪽 분류 태그와 큰 대사 한 줄을 둔다.
- 카드 전체가 선택 버튼이다. 선택 후 선택 카드만 금빛 테두리와 짧은 트로피 표시를 받고, 다음 대결로 전환한다.
- 하단에는 현재 라운드의 진행을 나타내는 짧은 점/막대만 둔다. 전체 대진표는 선택 화면에서 후보 카드보다 커지지 않는다.
- 세로 화면에서는 두 카드를 위아래로 쌓고 `VS`를 가운데에 둔다. 카드 이미지는 왼쪽, 텍스트는 오른쪽으로 한 줄에 압축할 수 있다.

### 최종 결과 화면 레이아웃

- 상단: 작은 게임명과 `🏆 최종 우승`만 둔다.
- iPad 가로 화면의 왼쪽 40%에는 우승 이미지 카드를 평소보다 크게, 금빛 외곽선과 함께 둔다. 우승 대사는 카드 아래 HTML 텍스트로 다시 표시한다.
- 오른쪽 60%에는 `WINNER ROUTE`, 큰 우승 대사, 우승 카드가 이긴 4~5개의 경로를 세로로 나열한다. 경로는 문장 하나씩만 보이는 가는 막대이며 작은 카드 갤러리로 만들지 않는다.
- 오른쪽 하단에는 `결과 포스터 저장`(강조), `다시 뽑기`, `처음으로` 버튼을 한 줄에 둔다. 결과 해설·훈계·성찰 문구는 넣지 않는다.
- 세로 화면에서는 우승 카드 → 우승 대사 → 경로 → 버튼 순으로 한 열에 쌓는다.

### 상태 모델

- `allReasons`: 52개 전체 데이터.
- `enabledReasons`: 이미지 검수를 통과한 항목만 포함.
- `tournamentSize`: 16 또는 32.
- `bracket`: 추첨된 카드와 각 라운드의 대진 상태.
- `selectedHistory`: 사용자가 고른 매 대결의 승자·패자·라운드 정보. 결과 포스터와 우승 경로에 사용.
- `soundEnabled`, `gameState`: 소리와 화면 전환 상태.
- URL·localStorage·서버에 투표 또는 개인 데이터를 저장하지 않는다.

### 정적 기술 조건

- HTML/CSS/브라우저 JavaScript만 사용한다. 빌드 도구, npm, 로그인, 데이터베이스, 서버, 런타임 이미지 API를 사용하지 않는다.
- 이미지 생성은 제작 단계에서만 수행한다. 배포된 GitHub Pages 앱은 정적 WebP만 불러 온다.
- 이미지가 모두 한꺼번에 내려받아지지 않도록 현재 대결과 다음 대결 카드만 preload하고, 대진표 썸네일은 `loading="lazy"`를 사용한다.
- 결과 포스터는 Canvas에서 한글 문구·선택 경로·우승 카드만 조합하고 PNG 다운로드를 제공한다. Canvas가 실패해도 결과 화면과 재시작은 정상 동작해야 한다.
- 복잡한 수식이 없으므로 MathJax/MathML을 추가하지 않는다.

## 6. 디자인·접근성·교실 사용성

- iPad A16 가로 `1180×820` CSS px에서 두 후보 카드, 선택 질문, 진행률, 음소거 버튼이 첫 화면에 함께 보여야 한다.
- iPad A16 세로 `820×1180` CSS px에서는 카드가 세로로 쌓여도 제목·문장·선택 영역이 겹치거나 잘리지 않아야 한다.
- 카드 이미지는 장식이 아니라 대결의 핵심 정보이므로, `alt`는 문장을 반복하지 않고 시각 농담을 짧게 설명한다. 예: `수학책과 포물선 밧줄에 발목이 잡힌 학생 피규어`.
- 카드의 정확한 대사는 이미지와 분리된 HTML 텍스트로 항상 읽을 수 있게 한다.
- 선택은 클릭·터치·키보드 모두 지원한다. 포커스 테두리를 숨기지 않는다.
- 이미지 로딩 실패 시에는 문장·분류색·단순 아이콘으로 구성된 카드로 대체해 게임을 멈추지 않는다.
- 교사 시연을 위해 `F` 키 또는 버튼의 전체 화면 안내는 넣을 수 있지만 브라우저 전체 화면 권한 실패 시에도 게임은 정상이어야 한다.

### 사후 학습효과 검토

- 16강 한 판이 교사의 클릭 기준 2~5분 안에 끝나는가.
- 학생이 별도 설명 없이 `더 고3 2학기다운 대사`라는 선택 기준을 이해하는가.
- 특정 학생을 지목하거나 실제 사정을 판정하는 장면 없이, 문장과 이미지의 과장으로 웃음이 나는가.
- 결과 화면이 훈계 없이 우승 카드·대진 경로·재시작으로 끝나는가.

### 사후 수식 표현 검토

판정 기준: **해당 없음**.

## 8. 완료 기준과 검증 방법

### 완료 기준

- 승인된 이미지가 있는 문장만 16강·32강 풀에 포함된다.
- 빠른 16강은 정확히 15회, 본선 32강은 정확히 31회의 선택으로 우승 문장을 정한다.
- 같은 한 판에서 같은 문장이 중복 출전하지 않으며, 승자는 다음 라운드에 정확히 한 번만 진출한다.
- 카드 이미지·대사·진행률·대진표가 선택 직후 일관되게 갱신된다.
- 결과 화면에서 우승 문장, 우승 카드, 우승 경로, `결과 포스터 저장`, `다시 뽑기`, `처음으로`가 보인다.
- 이미지 속에는 생성된 글자·숫자·로고·학교 식별 정보·실제 인물 닮은꼴이 없다.
- 배경음과 선택 효과음은 시작 후에만 재생되고, 음소거·재시작·페이지 숨김에서 중복 없이 정리된다.
- 콘솔 오류, 깨진 이미지, 로컬 절대경로, 런타임 API 키가 없다.
- iPad A16 가로·세로와 프로젝터 화면에서 후보 카드와 선택 문구가 읽힌다.
- `icebreaking/index.html`의 실제 링크·카드 이미지는 모든 파일이 생긴 뒤에만 추가한다.

### 검증 방법

1. `reasons.js`에서 `enabled: true` 항목 수가 16 또는 32 모드를 실행하기에 충분한지 확인한다.
2. 빠른 16강을 여러 번 시작해 매 판 16개가 중복 없이 추첨되고 15번 선택 후 결과가 나오는지 확인한다.
3. 본선 32강도 같은 방법으로 확인하고, 승자 경로가 대진표와 결과에 일치하는지 확인한다.
4. 마우스·터치·키보드로 각각 좌·우 카드를 선택해 동일하게 동작하는지 확인한다.
5. 카드 이미지가 문장과 일치하며, 위·아래 여백이 텍스트에 가려지지 않는지 확인한다.
6. 이미지 파일의 실제 크기·WebP 여부·용량을 점검하고, 문자가 생성되지 않았는지 육안으로 검수한다.
7. 네트워크를 느리게 한 상태에서 현재·다음 카드 preload와 이미지 실패 대체 카드가 게임을 멈추지 않는지 확인한다.
8. `결과 포스터 저장`으로 한글 문구와 우승 경로가 포함된 PNG가 내려받아지는지 확인한다.
9. 소리 켜기·끄기, 재대진, 탭 숨김, 페이지 이탈을 반복해 오디오 루프가 겹치지 않는지 확인한다.
10. iPad A16 가로 `1180×820`, 세로 `820×1180`, 교실 PC/프로젝터에서 카드·버튼·결과 화면을 확인한다.
11. 실제 파일이 모두 생긴 뒤 `icebreaking/index.html`의 링크, 이미지 경로, 브라우저 콘솔 오류를 확인한다.

## 9. 구현 시작 전 확정할 사항

- 이미지 52장을 모두 만든 뒤 시작할지, 우선 32장으로 본선부터 공개할지 결정한다. 권장 순서는 우선 32장 → 화면 검수 → 확장 20장이다.
- 결과 포스터의 가로 비율(프로젝터용 16:9, 공유용 4:5, 또는 둘 다)을 결정한다. 초기 버전은 공유하기 쉬운 4:5 한 장이면 충분하다.
- 교사가 대진을 통제하는 `교사용 고정 대진` 기능이 필요한지 결정한다. 필요하지 않으면 무작위 대진과 재시작으로 범위를 유지한다.
- 이미지 제작 전, 대표 4장(G3-01, G3-05, G3-38, G3-52)의 톤을 먼저 승인해 나머지 48장의 기준으로 삼는다.
